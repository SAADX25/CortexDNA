# Phase 2 UI/navigation migration plan

Approved Phase 1 checkpoint: eec6717bff431a1d162f98d493852fcecde55c75 (local only, same tree as update-31). Green starting Verify-Local baseline is artifacts/phase2-baseline.log. Phase 2 only; Phase 3 requires review.

- MainWindow becomes window chrome, sidebar, one content host, notifications and global progress/footer. Existing single-instance/tray/minimize/session-exit and awaited hardware/startup shutdown are retained.
- Home: live device/memory/network summaries and links to existing actions. Hardware: reuse HardwareDashboardControl with the same shared HardwareViewModel, no second monitor or timer. Startup: reuse StartupImpactControl and StartupViewModel; Windows startup services unchanged.
- Cleanup: present current cleanup categories and invoke the existing scan -> explicit selection/confirmation -> clean -> results path. No providers or Cleanup V3.
- Storage: present existing StorageList drive capacity/free space only. No analyzer, personal-file scan or deletion.
- Gaming: display only the existing automatic game-mode/throttling state. No new gaming optimization. Health: current telemetry and honest unavailable health-scan state; no health score, scan engine or animated core. Security: honest unavailable posture view, no scanner or repair actions.
- Tools: move the existing allowlisted Windows tool buttons/search here, preserving existing UAC behavior and shortcut. Settings: move theme/opacity controls, preserve existing theme_settings.json values and add persisted Reduced Motion; no monitoring/cleanup system changes. Diagnostics: show existing application version, privilege/status and log-location access; no uploads.
- Eleven separate views and page ViewModels; app-only PageId, NavigationStore, INavigationService, NavigationService and INavigationAware. Page state cached for one window; leaving a page detaches page-specific resources, closing disposes all pages and detaches shell subscriptions before completing the existing asynchronous shutdown. Existing main.HardwareVM and main.StartupVM test/shortcut access retained.
- Reusable Colors, Brushes, Typography, Spacing, Cards, Buttons, Navigation, ToggleSwitch, Dialogs, Progress and Animations dictionaries. Original cyan/navy Cortex identity, readable light theme, keyboard focus names and visible scrollbars. ViewModels emit semantic states, never color strings. StorageDrive color metadata becomes semantic state.
- Constructor-injected dialog UI service retains all destructive confirmations. Notification center is bounded and local; long operations expose shared shell state and real available progress. No cancellation control unless underlying operation supports it. Single-shot fade/8px slide and hover/selection effects; stop animation on replacement/hide/minimize, honor app Reduced Motion and Windows animation/high-contrast preference. No rendering loop.
- Deliberately exempt only approved UI files and color metadata from the frozen Phase 1 UI hashes; all system/feature implementation safety files and original test sources remain protected. Keep original Phase 1 manifest as historical evidence.
- Add lifecycle/fake/navigation/notification/semantic tests and isolated WPF page smoke with screenshot captures. Run offline restore, Debug/Release warnings-as-errors, standard tests and original WPF harness, safety hashes, CI failure probes, publish/installer check, complete diff whitespace checks. Record measurement limits and stop.

Agent Management, AI Agents, Agent Security Sandbox and sandbox deployment remain permanently excluded. No excluded pages, menus, flags, dependencies, scaffolding or reserved interfaces. No remote operations.
